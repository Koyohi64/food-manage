# 食材管理＆AIレシピ提案アプリ 機能仕様書（ざっくり版）

## 🎯 アプリのコンセプト

**「入力ゼロ・思考ゼロ・報告ゼロで、冷蔵庫の食材を美味しく使い切るアプリ」**
レシートや冷蔵庫の写真からAIが在庫を自動登録。期限ギリギリの食材を使ったレシピ提案はもちろん、AIレシピ以外で自炊した際も「〇〇を作ったよ」と音声やテキストで伝えるだけでAIが使用食材を推測し、在庫から自動消去。食材管理のあらゆる「めんどくさい」を徹底的に排除する。

## 🛠️ 技術スタック（想定）

- **フロントエンド・バックエンド:** Next.js (App Router)
- **データベース:** Neon (PostgreSQL), Prisma または Drizzle ORM
- **インフラ・デプロイ:** Vercel
- **AI連携:** Vercel AI SDK (OpenAI gpt-4o または Gemini 1.5 Pro) - ※Tool Calling（Function Calling）を活用して在庫更新を実行
- **認証:** NextAuth.js (Auth.js)

## 📦 機能要件（実装する機能リスト）

### 1. 食材の登録機能 (Input)

- **【MVP】手動登録:** 食材名と賞味期限（カレンダー入力 ＋「+3日」「+1週間」などの相対ボタン）を手動で登録する機能。
- **【拡張1】レシート画像解析登録:** レシートの写真をアップロードし、AIが食材名（汎用名に自動変換）と「予測される賞味期限」を一括抽出。ユーザーは一覧を見て修正・承認するだけ。
- **【拡張2】冷蔵庫ガサツ撮り登録:** 冷蔵庫内や野菜室の写真をアップロードし、画像認識AIが食材と鮮度（おおよその残り期限）を推測して一括登録。

### 2. 食材の管理・ダッシュボード機能 (Management)

- **【MVP】期限アラート表示:** ホーム画面のトップに、賞味期限が「今日まで/切れ（赤）」「あと3日以内（黄）」の食材を優先的にリスト表示。安全な食材（緑）は下部に配置。
- **【MVP】在庫一覧・編集・削除:** 現在の在庫リストの閲覧、詳細な編集機能。直感的に修正できる機能（「＋」「－」ボタンでの素早い分量調整）。

### 3. AIレシピ提案機能 (Output)

- **【MVP】ワンタップレシピ生成:** 期限が近い食材に最初からチェックが入った状態で「レシピを生成」ボタンを押すと、AIがレシピを考えてくれる。
- **【MVP】ストリーミングUI:** AIの思考中、レシピのタイトル→材料（基本調味料含む）→手順が1文字ずつパラパラと画面に表示される（待ち時間のストレス軽減）。
- **【拡張】再生成＆条件追加:** 「もっとガッツリ系で」「火を使わないで」など、条件を足してレシピを引き直す機能。

### 4. 在庫連動・調理記録機能 (Action)

- **【MVP】「作った！」ボタン（自動消費）:** 提案されたAIレシピ画面の「作った！」ボタンを押すと、そのレシピに使われた食材がデータベースの在庫から自動的に削除（またはマイナス）される。
- **【MVP】ズボラ事後報告（音声・テキストAI消費）:** \* ユーザーが「カレーを作った」「豚肉と玉ねぎを使った」とテキストや音声で入力。
    - AIが現在の在庫データと照らし合わせ、「在庫にある豚肉と玉ねぎを消費しました」と自動で在庫を更新する（Vercel AI SDKのTool Calling機能を使用）。
- **【拡張】料理履歴とギャラリー:** AI提案レシピ、および事後報告で作った料理の履歴を保存・閲覧できる機能。

### 5. ユーザー認証・設定 (Auth/Settings)

- **【MVP】アカウント登録/ログイン:** password, mailadress方式。ゆくゆくはGoogleログインなどのソーシャルログイン。自分の冷蔵庫データだけを見られるようにする。

## 📱 画面構成（主要ページ）

1.  **ログイン画面**
2.  **ホーム（ダッシュボード）**
    - 期限アラートリスト（レシピ生成への導線）
    - 在庫一覧（**各アイテムの横に＋/－ボタン、スワイプ削除など、手動調整しやすいUI**）
    - **上部または下部固定の「ズボラ報告バー」**（テキスト入力欄 ＋ マイクボタン。「何を作った？」とプレースホルダーを表示）
    - 右下フローティングアクションボタン（＋）→ 食材の新規追加メニューへ
3.  **食材追加モーダル/ページ**
    - 「カメラでレシートを撮る」「冷蔵庫を撮る」「手動で入力する」の選択肢。
    - AI抽出結果の確認・編集・確定画面。
4.  **レシピ提案画面**
    - 生成されたレシピの表示。
    - 「作った！（在庫から削除）」ボタン。
5.  **マイページ**
    - 過去の料理履歴、ログアウト。

## 🗄️ データベース設計のイメージ（Neon / PostgreSQL）

最初は以下の3つのテーブルがあれば十分動き出せます。

1.  **`User` (ユーザー):** ID, 名前, メールアドレス
2.  **`Item` (食材):** ID, ユーザーID, 食材名, 賞味期限(`expiration_date`), 登録日
3.  **`RecipeHistory` (履歴):** ID, ユーザーID, レシピタイトル(AI生成、または事後報告テキスト), 内容, 作成日
